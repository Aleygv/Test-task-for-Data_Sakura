# Zoo World (Data Sakura — Test Task)

3D-симулятор жизненного цикла и пищевой цепочки животных на Unity с видом сверху (Top-Down). Проект выполнен в качестве тестового задания с фокусом на масштабируемую архитектуру, принципы SOLID и чистый код.

---

## 📋 Требования технического задания (ТЗ)

1. **Геймплей:**
   - Каждые 1–2 секунды на арене случайным образом спавнится животное.
   - Животные перемещаются по арене и остаются в границах видимости экрана (при выходе за пределы — меняют направление движения обратно в экран).
   - Физические коллизии между объектами.
2. **Пищевая цепочка:**
   - **Жертвы (Prey, например Лягушка / Frog):** совершают прыжки раз в `X` секунд на фиксированную дистанцию. При столкновении двух жертв — они отскакивают друг от друга по законам физики. При встрече с хищником — жертва погибает и исчезает с арены.
   - **Хищники (Predator, например Змея / Snake):** непрерывно перемещаются с постоянной скоростью. При столкновении с жертвой — съедают её (над хищником появляется плашка «Tasty!»). При столкновении двух хищников — один случайным образом (50/50) выживает, а второй погибает.
3. **Интерфейс (UI):**
   - В правом верхнем углу расположен счётчик погибших жертв и хищников, выполненный на uGUI.
4. **Главный фокус ТЗ:**
   - Архитектура животных должна быть прозрачной, легко расширяемой и поддерживаемой (с расчётом на возможное добавление сотен и тысяч новых типов животных — птицы, пауки, рыбы, крабы и т.д.).
   - Без использования ECS.

---

## 🛠 Стек технологий

- **Unity 6** (6000.3+)
- **Zenject** — Dependency Injection (разделение ProjectContext и SceneContext, инверсия зависимостей).
- **UniTask** — высокопроизводительное асинхронное программирование (контроль жизненного цикла через `destroyCancellationToken`, перемещения, отскоки).
- **Addressables** — асинхронная загрузка и инстанцирование префабов.
- **Unity NavMesh** — навигация и ограничение перемещения мобов по поверхности арены.
- **DOTween** — анимации плашек и UI.
- **TextMeshPro + uGUI** — отображение интерфейса.

## 🏛 Архитектурные решения и паттерны

### 1. Разделение модели и представления (Model-View Separation)
- **Domain-модель (Чистый C# / Бизнес-логика):** классы `AnimalBase`, `Frog`, `Snake` реализуют интерфейс `IAnimal`. Они не зависят от `MonoBehaviour`, не знают про рендеринг, меши и слои физики Unity. Вся логика принятия решений («куда пойти», «когда прыгнуть», реакция на смерть) изолирована и может быть покрыта Unit-тестами без запуска сцены.
- **Представление (Unity GameObject / Физика):** компонент `AnimalReference` (MonoBehaviour) выступает мостом (Mediator) между Unity-коллайдерами и C#-моделью.

### 2. Паттерн «Мост» / «Стратегия» для движения (Bridge & Strategy Pattern)
- Логика перемещения вынесена в независимый интерфейс `IMovement`.
- `MovementBase` — базовый класс для Unity-компонентов движения, инкапсулирующий общие свойства (`NavMeshAgent`, координаты, унифицированную логику физического отскока `Bounce()` с защитой от повторного вызова).
- `JumpMovement` — баллистическое параболическое перемещение (прыжок).
- `LinearMovement` — непрерывное линейное перемещение через `NavMeshAgent`.
- **Преимущество:** Любое животное может получить любой тип движения через префаб/конфиг без изменения кода самого животного (например, можно легко создать прыгающую змею или летающую лягушку).

### 3. Матрица взаимодействий (Interaction Matrix)
В сервисе `AnimalCollisionResolver` правила взаимодействия между ролями животных (`Prey` vs `Prey`, `Predator` vs `Prey`, `Predator` vs `Predator`) вынесены в матрицу на основе словаря делегатов. Это исключает ветвящиеся цепочки `if-else` и делает правила пищевой цепочки легко расширяемыми при добавлении новых ролей (например, травоядные, падальщики, нейтральные).

### 4. Конфигурация животных (Data-Driven)
- Настройки животных (`AnimalType`, `AnimalRole`, путь к префабу Addressables) вынесены в `AnimalConfig` и централизованный реестр `GameConfigs`.
- Фабрика `AnimalFabric` инстанциирует сущности по конфигу, связывая визуальный префаб с C#-моделью через DI.

### 5. Архитектура UI (MVP)
Интерфейс счётчиков реализован по паттерну Model-View-Presenter:
- **Model:** события смертей животных из `IAnimalRegistry`.
- **View:** `AnimalViewCounter` (uGUI + TextMeshPro).
- **Presenter:** `AnimalScorePresenter` — слушает события модели и обновляет View без прямой связанности.

### 6. Безопасная асинхронность и отмена задач
Во всех асинхронных методах (`PerformJumpAsync`, `BounceAsync`) передаётся нативный `destroyCancellationToken` с обработкой `OperationCanceledException`. При уничтожении животного во время прыжка или отскока все асинхронные задачи корректно прерываются без `MissingReferenceException` и утечек памяти.

## 📂 Структура проекта

```text
Assets/
├── AddressableResources/      # Префабы животных и UI
└── _Project/
    └── Logic/
        ├── Entities/          # Модели и сущности
        │   ├── AIMovement/    # Компоненты движения (MovementBase, JumpMovement, LinearMovement)
        │   ├── Animals/       # C# классы животных (AnimalBase, Frog, Snake)
        │   ├── AnimalConfig.cs
        │   ├── AnimalReference.cs  # Мост MonoBehaviour <-> IAnimal
        │   ├── IMovement.cs
        │   └── SpawnPositionProvider.cs
        ├── Infrastructure/    # Точки входа, циклы игры и инсталлеры Zenject
        │   ├── Bootstrapper.cs
        │   ├── GameConfigs.cs
        │   ├── GameCycleScript.cs
        │   └── SceneInstaller.cs
        ├── Services/          # Сервисы (фабрика, коллизии, реестр, провайдер ассетов)
        │   ├── AnimalCollisionResolver.cs
        │   ├── AnimalFabric.cs
        │   └── AnimalRegistry.cs
        ├── UI_Logic/          # MVP логика интерфейса (Presenter, View, Factory)
        └── Extensions/        # Методы расширения (CameraExtensions)
```

## ▶️ Запуск проекта

1. Открыть проект в **Unity 6** (версия `6000.3.15f1` или новее).
2. Открыть сцену `Assets/Scenes/SampleScene.unity`.
3. Нажать кнопку **Play**. Животные начнут автоматически спавниться на арене в соответствии с правилами ТЗ.
